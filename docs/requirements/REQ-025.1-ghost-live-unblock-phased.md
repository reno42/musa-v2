## 1. Trabajo para el IDE agent — 4 items, en este orden

### Item 1 — Unificar fuente de verdad de roles + saneamiento de defaults (barato, evita el falso "roté la key y sigue fallando")
1. `resolveGhostLlm()` (ghostBridge.ts) debe leer los roles de la MISMA fuente que el Dashboard: server prefs (ya existe el fetch de perfil) con localStorage como fallback optimista mientras carga. Un solo orden de precedencia, documentado en el código.
2. Reemplazar TODOS los defaults `deepseek-v4-pro` por el primer modelo válido del provider (`getProvider(id).models[0]` / `defaultModelFor`). Grep de verificación: `grep -rn "deepseek-v4-pro" src/` debe devolver 0 resultados.
3. Al resolver el LLM, si el modelo configurado no está en el lineup del provider (`!getProvider(prov.id)?.models.includes(model)`), caer a `defaultModelFor(prov.id)` y registrar la corrección en el job.

### Item 2 — Preflight BYOK (desbloquea el mensaje honesto)
Lógica en `resolveGhostLlm` ANTES de reclamar el job (no endpoint nuevo si puede vivir client-side; endpoint `POST /api/ghost/preflight` solo si el ping necesita server-side):
1. Ping mínimo al proveedor (max_tokens ~1).
2. Clasificar: `BYOK_MISSING` (sin key) / `BYOK_INVALID` (401/403) / `BYOK_INSUFFICIENT_BALANCE` (402 — DeepSeek la usa cuando se acaba el saldo) / `BYOK_WRONG_ENDPOINT` (404/HTML) / `MODEL_FORBIDDEN` / `PROVIDER_RATE_LIMITED` (429) / `PROVIDER_UNAVAILABLE` (5xx/red).
3. Devolver `{ ok, provider, model, keySource, last4, reasonCode }` — NUNCA plaintext ni headers.
4. `ghost_perform` rechaza ANTES de crear el job con el reasonCode + instrucción de rotación ("Configuración → Invita IAs → <provider>"). Cero mutación, cero headless fallback.

### Item 3 — Telemetría mínima del job
En `ghost_jobs.result` o columna jsonb `trace` (NO migración de tablas nuevas): `provider`, `model`, `keySource`, `last4`, `phase`, `reasonCode`, timestamps. Mínimo viable: `accepted`, `claimed`, `llm_first_call`, `done|failed` con `phase`+`reasonCode`. Con esto el próximo fallo se diagnostica en 1 query, no en 30 min de agente adivinando.

### Item 4 — Higiene de deploy (higiene, no feature)
Commits organizados: `fix(worker): self-fetch statics via ASSETS binding` (patch v60 de `worker/index.js`), y triage de los untracked (debug assets → .gitignore). Deploy de prod = 1:1 con un commit de main. **No pushear sin orden explícita de Ren.**
