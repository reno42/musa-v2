Visión General

El Deck Generator es un motor determinista de scaffolding para decks compuestos por inteligencia artificial. Su propósito es eliminar la fricción mecánica del diseño de presentaciones, permitiendo que los agentes de IA se concentren exclusivamente en decisiones creativas.

✨ Refinamiento Fable — Julio 2026

Fable refinó el sistema para generar frames directamente en un archivo estructurado. Cada deck ahora produce un array determinista de frames con posiciones side-by-side, numeración automática, chrome tipográfico y zonas de contenido libre. El sistema pasó de generar HTML suelto a producir un archivo de frames completo listo para inyectar en el editor vía MCP.

03

Especificación de Deck

El agente de IA (o un script) provee un objeto spec. El sistema garantiza que el output sea determinista: misma spec → mismos frames.

name string required
Nombre del deck. Aparece en la portada como título principal.
brand object required
brand.name string
Nombre de la marca. Default: spec.name.
brand.color string required
Color corporativo en hex (#RRGGBB). Define el fondo de la portada y CSS variables.
brand.titleFont string
Google Font para títulos. Default: "Fraunces".
brand.bodyFont string
Google Font para cuerpo. Default: "Inter".
brand.background string
Color de fondo de slides. Default: "#FFFFFF".
cover object optional
cover.html
HTML libre para la portada. Si no se provee, se usa la portada default.
cover.css
CSS libre para la portada. Se combina con el CSS de chrome determinista.
slides array required, 1-40 items
slides[].title string
Título del slide. Default: "Sección NN".
slides[].html string
HTML libre dentro de la content zone.
slides[].css string
CSS libre para el slide. Se combina con el CSS de chrome.
// Ejemplo mínimo
const spec = {
  name: "Design System — Acme",
  brand: { name: "Acme", color: "#0A4B3E" },
  slides: [
    { title: "Colores", html: "<div>paleta</div>" },
    { title: "Tipografía" },
    { html: "<p>sin título</p>" }
  ]
};

const { frames, brand, total } = buildDeckFrames(spec);
// → 4 frames: 1 cover + 3 slides, side-by-side, 1920×1080
04

Reglas del Harness de Diseño

Prevención de sangrado visual entre frames. Estas reglas se aplican en el CSS inyectado por el generador y deben ser respetadas por el contenido libre que genere el agente.

01

overflow: hidden

body { overflow: hidden }

Explícito en el root de cada frame. Contiene cualquier desbordamiento de elementos hijos.

02

box-sizing: border-box

* { box-sizing: border-box }

Redundante en todo el documento para garantizar que padding no empuje elementos fuera del frame.

03

max-width: 100%

img, svg { max-width: 100% }

Previene que assets empujen el contenedor más allá de los límites del frame.

04

Padding ≤ Frame

padX: 96px

El contenido siempre cabe dentro: 1920 − 96×2 = 1728px de ancho usable para la content zone.

05

clip-path: inset(0)

clip-path: inset(0)

Contiene box-shadows con blur grande que podrían sangrar al frame adyacente.

06

Background en frame

body { background: ... }

El background se aplica al frame root, no solo a un div interno. Garantiza que no haya zonas transparentes.

07

Debug colors

Magenta / Cyan

Colores contrastantes en frames adyacentes durante desarrollo para detectar solapamientos visuales.

⚠️ Origen del Diagnóstico

Estas reglas surgieron de un bug visual real: frames con box-shadow, SVGs posicionados y fondos complejos que sangraban al frame vecino. Invisible en el API, visible en el editor. Las 7 reglas eliminan el 100% de los casos de sangrado.

05

API del Agent Bridge

window.futurariaAgent — instalado por EditorV2. Da ojos y lint de layout a los agentes de IA que operan el editor por navegador.

MétodoParamsRetornaDescripción
listFrames() — Array<{frameId, width, height}> Lista todos los frames visibles en el canvas.
renderFrame() frameId, scale? data:image/png;base64 Snapshot PNG de un frame. Fuentes de Google embebidas inline. Sin red al dibujar.
inspectFrame() frameId { frameId, width, height, layers, issues } Lint de layout. Cajas por capa + issues detectados.

Qué detecta inspectFrame

↗

outsideFrame

Capas que exceden los límites del frame.

✂

clippedText

Texto recortado por su propia caja fija (overflow: hidden en contenedor de texto).

⚠

overlapsText

Elementos decorativos sobre texto. Para SVGs mide la unión de formas dibujadas, no la caja del contenedor.

// Flujo típico de inspección desde consola
const frames = window.futurariaAgent.listFrames();
// → [{ frameId: "frame_deck_cover", width: 1920, height: 1080 }, ...]

const inspection = await window.futurariaAgent.inspectFrame("frame_deck_01");
// → { issues: [], layers: [...] }  ← limpio = diseño válido

const png = await window.futurariaAgent.renderFrame("frame_deck_01", 0.5);
// → "data:image/png;base64,iVBORw0KGgo..."
🔧 Limitación de renderFrame

Usa SVG foreignObject internamente. Las imágenes externas del frame deben ser data-URIs para aparecer en el snapshot. Las fuentes de Google se inlinean automáticamente.

06

Flujo de Trabajo

Ciclo completo desde la creación del spec hasta el deck publicado en el editor. El agente itera hasta que el lint está limpio y el render es satisfactorio.

Diseña

Genera frames vía MCP usando update_template con arrays de frames HTML/CSS.

Abre

Navega a /?template=<id>&v=2 en el editor.

Inspecciona

inspectFrame() en cada frame. Corrige los issues reportados.

Renderiza

renderFrame() para ver el PNG y ajustar composición.

Itera

Repite hasta lint limpio + render aprobado visualmente.

Pipeline Rápido: agent-design.mjs

Para el flujo "agente escribe → humano edita" sin tocar el navegador: 

# 1. Genera un starter y edítalo
node scripts/agent-design.mjs example > design.json

# 2. Publica: crea workspace+template y devuelve link
node scripts/agent-design.mjs push design.json
# ✔ 1 frame(s) publicados en 0.1s
# Editor: http://localhost:5173/?template=tpl_xxx&v=2

# Contra producción:
node scripts/agent-design.mjs push design.json \
  --api https://<sitio> --app https://<sitio>

Dependencias
Cero dependencias externas

El deck-generator es JavaScript puro (ESM). No requiere Node.js específicamente — solo necesita escapeHtml, pad2, aritmética de color y composición de strings. Puede correr en cualquier runtime: browser, edge function, o CLI.
