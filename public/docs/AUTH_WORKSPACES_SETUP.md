# Auth and shared workspaces

The application uses Supabase Auth for identities and `workspace_members` for authorization. A user account and a workspace are different records: every account owns a personal workspace and may also belong to any number of shared workspaces.

## Apply the database migration

Run `supabase_migrations_v11.sql` after v10. The migration is idempotent and provides:

- automatic profile and personal-workspace provisioning for new and existing Auth users;
- invitation expiry, decline, revocation and delivery state;
- atomic invitation acceptance bound to the signed-in user's verified email;
- RLS and RPC permissions that prevent anonymous acceptance or cross-workspace access.

After production accepts the migration, update `.migration-version` to `v11` in a separate commit so strict deployments know the schema is ready.

## Environment variables

Set these only in the server/runtime environment:

```text
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
SUPABASE_SECRET_KEY=sb_secret_...
SAAS_APP_URL=https://YOUR_APP_DOMAIN
```

`SUPABASE_SERVICE_KEY` remains supported as a legacy server-side fallback. Secret/service keys must never use the `VITE_` prefix or be exposed to the browser.

## Supabase Auth configuration

In **Authentication → URL Configuration**:

1. Set **Site URL** to the production application URL.
2. Add the production URL and local development URL to **Redirect URLs**. The invitation and recovery flows preserve `?invite=...` and `?reset=1` parameters.

In **Authentication → Sign In / Providers → Email**:

1. Enable email/password authentication.
2. Keep email confirmation enabled for production.
3. Set the minimum password length to at least 10 characters.
4. Configure custom SMTP before a public launch so confirmation, recovery, invitation and magic-link messages have production deliverability.

Customize the **Confirm signup**, **Invite user**, **Magic Link**, **Change Email Address** and **Reset Password** templates with the product name and support address. The links generated by Supabase must keep their `RedirectTo` destination.

## Invitation behavior

- Existing accounts receive a Supabase magic link and see an explicit Accept/Decline screen.
- New addresses receive a Supabase account invitation, choose their name and password, then explicitly accept the workspace.
- Administrators always receive a copyable workspace invitation link as a fallback.
- Pending invitations appear both under **Workspace → Equipo** for administrators and under **Workspace → Cuenta** for the recipient.
- Resending rotates the secret token and extends expiry; revoking immediately invalidates the previous link.
